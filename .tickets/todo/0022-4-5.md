# Ticket #0022: スタイルシステム再設計 - 4-5色のシンプル統一

## Description

現在のFLOW_STYLESが複雑すぎるため、Bootstrap/Tailwind標準の4-5色シンプルスタイルシステムに再設計する。保守性と一貫性を大幅に向上させる。

## 現在の問題

### 複雑すぎるスタイル分類
```typescript
// 現在：25個以上のスタイル定数
FLOW_STYLES.gitSuccess, gitWarning, gitInfo, gitCommand
FLOW_STYLES.ticketId, ticketTitle, ticketStatus, statusTransition  
FLOW_STYLES.feature, section, command, option, progress
FLOW_STYLES.title, success, warning, error, info, path, count, code, dim
```

### 問題点
- **覚えにくい**: 25個以上のスタイル名
- **判断に迷う**: どのスタイルを使うべきか不明確
- **保守困難**: 似たような意味のスタイルが複数存在
- **意味論混在**: セマンティック/用途別/表示形式が混在

## 新設計提案

### シンプル4色システム（推奨）
```typescript
export const STYLES = {
  success: chalk.green,   // 成功操作（✅作成完了、ブランチ切り替え成功）
  info: chalk.blue,       // 情報表示（🔍検索結果、📋詳細情報）  
  warning: chalk.yellow,  // 注意・警告（⚠️警告、📝手動操作必要）
  danger: chalk.red,      // エラー・危険（❌失敗、🚫禁止操作）
  muted: chalk.gray      // 補助情報（コマンド例、ヘルプテキスト）
} as const;
```

### 使用例
```typescript
// Before (複雑)
FLOW_STYLES.gitSuccess('✓ ブランチ作成成功')
FLOW_STYLES.gitWarning('⚠️ フェッチ失敗')  
FLOW_STYLES.gitCommand('git checkout main')
FLOW_STYLES.statusTransition('todo → doing')

// After (シンプル)
STYLES.success('✓ ブランチ作成成功')
STYLES.warning('⚠️ フェッチ失敗')
STYLES.muted('git checkout main') 
STYLES.muted('todo → doing')
```

## 設計原則

### 1. セマンティック優先
- 見た目（色）ではなく意味（成功/警告等）で分類
- 将来的な色変更にも対応可能

### 2. 標準準拠
- Bootstrap/Tailwind/Material Design標準
- 他のUIライブラリとの一貫性

### 3. 判断簡単
- 成功→success、警告→warning、エラー→danger
- 迷いなく選択可能
