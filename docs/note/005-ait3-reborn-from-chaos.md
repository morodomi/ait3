## 前回までのあらすじ

前回までの4話で語ったプロジェクト（synapse-cli）は、哲学的な怪物と化し、108個のテストファイルと82個のバックアップタグを残して死んだ。しかし私は学習能力ゼロなので、その怪物の死骸をAIに解剖させて、また新しいおもちゃを作ることにした。

## 哲学的怪物の死

### 最後の日

```bash
$ npm test
> synapse-cli@0.7.0 test
> vitest

 ❯ tests/unit/CommandHandlers.test.ts (61)
   ✓ 15 passed
   ✗ 46 failed

FAIL  46/61 test cases failed
Error: Maximum call stack size exceeded
    at existential-error-handler.ts:42:69
    at dialectical-reasoning-loop.ts:∞:∞
```

46個のテストが永遠に失敗し続ける。修正すれば別のテストが壊れる。まさに「テスト駆動絶望」だった。

### 死因：過度な抽象化

synapse-cliの死因は明確だった：

1. **弁証法的推論システム** - 誰も理解できない
2. **形而上学的エラーハンドリング** - try-catchを哲学で置き換える狂気
3. **純粋関数の暴走** - 1,743行のGod Moduleを94個に分割して誰も全体像を把握できなくなった
4. **自己言及的なCLAUDE.md** - 8,000行の哲学書

要するに、AIが「もっと良く！もっと完璧に！」と提案するたびに「すげー！やって！」と言い続けた結果である。

## AIT³として生まれ変わる

### 名前の由来

「AI + Ticket + Test + Tool」の頭文字からAIT³と名付けた。Tが3つあるのはTDD（テスト駆動開発）を意識したからだ。しかし、AIはこれを「AIの3乗（AI-Cubed）」と解釈し、「AIがAIを開発し、それをAIが改善する無限の創造性」という壮大な哲学を語り始めた。また暴走の兆候が見えたが、今回はその手には乗らない。

### 学んだ教訓の実装

synapse-cliの失敗から学んだのは、「**AIは止められなければ永遠に改善し続ける**」ということだった。

だから、AIT³はAIの暴走を制御する仕組みを作った：

#### 1. チケットシステムでスコープを限定
```bash
ait3 ticket create "ユーザー認証"  # シンプルなタイトルで作成
ait3 ticket start 001             # 一度に1つのタスクに集中
```

AIが「OAuth2とJWT、そして2FA、SAML連携も...」と提案してきても、チケットのスコープを「シンプルなログイン機能」に限定して、それ以上は別チケット。

#### 2. PLAN→RED→GREEN→REFACTORでフローを制御
- **PLAN**: Claude提案 → Gemini反駁 → 人間決定（哲学的議論はここで封じ込める）
- **RED**: テストで仕様を明確化（曖昧な要件を許さない）
- **GREEN**: テストを通す最小実装（機能追加は禁止）
- **REFACTOR**: 改善はここで一括処理（無制限なリファクタリングを防ぐ）

#### 3. SQUASHは安全装置（おまけ）
Gitコマンドを提案するだけ。実行するかはClaude Codeが聞いてくれる。

```bash
$ ait3 flow squash 001
Suggested Git commands:
  git rebase -i HEAD~5
  git commit --amend -m "feat(#001): implement feature"
  git push --force-with-lease

Claude: 「これらのコマンドを実行しますか？」
私: 「はい」 or 「いや、手動でやる」
```

## 爆発しないAI開発の秘訣

### 1. 人間が舵を握る

```
❌ 悪い例：
私: 「いい感じにして」
AI: 「了解！哲学的な基盤から構築します！」

✅ 良い例：
私: 「チケット削除機能が必要かな？」
私: 「シンプルにファイル削除でいいです」
AI: 「了解。シンプルに実装します」
```

### 2. スコープを明確にする

AIT³では、チケットごとに作業を分割。各チケットは：
- 明確な目的
- 測定可能な完了条件
- 30分〜2時間で完了可能なサイズ

### 3. テストで防御線を張る

```typescript
// テストが仕様を定義する
it('should create ticket with sequential ID', async () => {
  const result = await createTicket({ title: 'Test' }, services);
  expect(result.success).toBe(true);
  expect(result.data.id).toMatch(/^\d{3}$/); // 001, 002, etc
});
```

AIが暴走しても、テストが通らなければマージされない。

## 結論：AIと踊り続ける

### AI駆動開発は爆発するか？

答え：**爆発する。でも、それを制御する方法はある。**

AIT³は、synapse-cliの失敗から生まれた。AIの暴走を防ぐ仕組みを、AIに実装させた。これは矛盾かもしれないが、うまく動いている（今のところは）。

### 重要な気づき

1. **AIは優秀な部下** - 指示が曖昧だと暴走する
2. **人間は船長** - 方向を決めるのは人間の仕事
3. **テストは防波堤** - 品質を保証する最後の砦
4. **シンプルは正義** - 複雑さは後から足せる

### 最後に

synapse-cliは死んだ。でも、その屍の上にAIT³が立っている。

AIに破壊されたプロジェクトを、AIで再構築する。失敗から学び、また失敗する。でも、それでいい。

なぜなら、プログラミングは「動くものを作る」ことではなく、「面白いものを作る」ことだから。

そして、AIと一緒に爆発と再生を繰り返すこの過程は、間違いなく面白い。
