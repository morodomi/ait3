# Claude Code .claude/commands 調査結果

## 概要

`.claude/commands`ディレクトリは、Claude Codeで使用できるカスタムコマンドを定義する場所です。これらのコマンドは自動読み込みされず、意識的に実行する必要があります。

## コマンドの実行方法

- **実行方法**: `/command-name`（例：`/gemini`, `/orchestrator`）
- **引数の渡し方**: `/gemini analyze this code`のように引数を渡せます
- **自動実行**: されません。手動で明示的に実行する必要があります

## コマンドの配置場所

1. **プロジェクト固有コマンド**: `.claude/commands/` 
   - プロジェクトに特化したコマンド
   - バージョン管理対象

2. **個人用コマンド**: `~/.claude/commands/`
   - すべてのプロジェクトで利用可能
   - 個人の作業環境に依存

## 既存コマンドの分析

### 現在配置されているコマンド

| コマンド | ファイルサイズ | 用途 | 主な機能 |
|---------|------------|------|---------|
| ait3 | 5KB | AIT³ワークフロー | TiDDワークフローの説明とコマンド一覧 |
| gemini | 10KB | 大規模コードベース分析 | @syntax、巨大コンテキストウィンドウ活用 |
| npm | 8.8KB | npmスクリプト統合 | TiDDフェーズとnpmスクリプトの統合 |
| orchestrator | 3.3KB | タスク分割 | 複雑タスクを逐次ステップに分割 |
| similarity-ts | 11.7KB | コード重複検出 | リファクタリング支援 |

### 各コマンドの特徴

#### 1. ait3コマンド
- **目的**: AIT³ワークフローの説明と使い方
- **内容**: PLANNING → RED → GREEN → REFACTOR → SQUASH の詳細説明
- **使用例**: `/ait3` でワークフロー確認

#### 2. geminiコマンド  
- **目的**: 大規模コードベース分析
- **特徴**: @構文でファイル/ディレクトリ指定
- **使用例**: 
  ```bash
  /gemini @src/ 全体のアーキテクチャを分析して
  /gemini @package.json 依存関係の問題点を指摘して
  ```

#### 3. npmコマンド
- **目的**: npmスクリプトとTiDDワークフローの統合
- **内容**: 各フェーズ（RED/GREEN/REFACTOR）でのnpmコマンド使用法
- **使用例**: `/npm` でTiDD対応npmスクリプト確認

#### 4. orchestratorコマンド
- **目的**: 複雑なタスクの構造化
- **内容**: Sequential steps with parallel subtasks
- **使用例**: `/orchestrator analyze test lint and commit`

#### 5. similarity-tsコマンド
- **目的**: コード重複検出とリファクタリング支援
- **内容**: REFACTORフェーズでの活用方法
- **使用例**: `/similarity-ts` でコード重複分析ガイド確認

## コマンドファイルの構造

### 基本構造
```markdown

コマンドの説明と使用方法

## 使用例
具体的な使用例

$ARGUMENTS - ユーザーが指定した引数に置換される
```

- `$ARGUMENTS`: コマンド実行時に渡された引数に置換される
- サブディレクトリ対応: `frontend/component.md` → `/frontend:component`

## インストール方法の現状と提案

### 現状
- `ait3 install command ait3` のみ実装済み
- 他のコマンド（gemini、npm等）は手動配置

### 提案
```bash
ait3 install command gemini        # geminiコマンドインストール
ait3 install command --all         # 全推奨コマンド一括インストール
ait3 install command --category development  # カテゴリ別インストール
```

## Claude Code設定システム

### 設定ファイルの階層構造

1. **`~/.claude/settings.json`**: グローバル設定（全プロジェクト共通）
2. **`.claude/settings.json`**: プロジェクト固有設定（バージョン管理対象）
3. **`.claude/settings.local.json`**: ローカル設定（バージョン管理外）

### 主要な設定項目

#### permissions（権限管理）
```json
{
  "permissions": {
    "allow": [
      "Bash(npm run test:*)",
      "Bash(git add:*)",
      "Bash(ls:*)"
    ],
    "deny": [
      "Bash(rm:*)",
      "Bash(curl:*)",
      "Bash(wget:*)"
    ]
  }
}
```

#### env（環境変数）
```json
{
  "env": {
    "CLAUDE_CODE_ENABLE_TELEMETRY": "false",
    "MAX_THINKING_TOKENS": "30000",
    "CLAUDE_RESPONSE_LANG": "ja"
  }
}
```

#### その他の設定
- `apiKeyHelper`: カスタム認証設定
- `cleanupPeriodDays`: チャット履歴のクリーンアップ期間
- `includeCoAuthoredBy`: GitコミットへのCo-authored-by署名

## Claude Codeフック（Hooks）システム

### フックとは

ユーザー定義のシェルコマンドで、Claude Codeのライフサイクルの特定のポイントで実行されます。

### フックの用途

- **ログ記録**: ツール使用状況の記録
- **自動フォーマット**: コード変更後の自動整形
- **カスタム権限**: ツール実行の独自ルール適用

### フックの作成方法

1. `/hooks`コマンドを実行
2. フックイベントを選択（例：`PreToolUse`）
3. 対象ツールを指定（例：`Bash`）
4. 実行するシェルコマンドを定義
5. ユーザー/プロジェクト設定に保存

### フックの種類

#### PreToolUse
- **実行タイミング**: ツール実行前
- **用途**: 検証、ブロック、前処理
- **例**: 危険なコマンドのチェック

#### PostToolUse  
- **実行タイミング**: ツール実行成功後
- **用途**: 後処理、ログ、自動フォーマット
- **例**: ファイル変更後の自動整形
